## 1. 风格融合方案（A + B + E + d 怎么合）

- **E 编辑/杂志风（骨架）**：超大衬线标题、大留白、1px 细线分隔、栏目标签（如 "01 — 目的地"）、竖排小字装饰
- **A 玻璃拟态（层叠）**：卡片用半透明白底 `rgba(255,255,255,0.6)` + `backdrop-filter: blur(16px)` + 1px 白色描边，叠在彩色渐变背景上
- **B 新拟态（点睛）**：按钮、标签、页码等小元素用浅灰底 + 双向阴影做凸起/凹陷
- **d 多彩活力（灵魂）**：每个城市一个专属高饱和色，背景用大面积彩色渐变色块

### 2.2 间距（基数 8px，最小粒度 4px）

`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96 / 128` px
区块之间的垂直间距：移动端 64px，桌面端 128px。

### 2.3 圆角

| 元素 | 圆角 |
|---|---|
| 按钮 | 14px（胶囊按钮 999px） |
| 卡片 | 20px |
| 大图/主视觉图 | 24px |
| 小标签 Tag | 8px |

### 2.4 阴影（具体值）

| 用途 | 值 |
|---|---|
| 玻璃卡片常态 | `0 8px 32px rgba(27,42,78,0.10)` |
| 新拟态凸起 | `8px 8px 20px rgba(174,174,192,0.35), -8px -8px 20px rgba(255,255,255,0.95)` |
| 新拟态凹陷 | `inset 6px 6px 12px rgba(174,174,192,0.40), inset -6px -6px 12px rgba(255,255,255,0.90)` |
| 卡片悬停抬升 | `0 20px 44px rgba(255,92,53,0.22)` |

### 2.5 字体

| 用途 | 字体族 | 字号 | 字重 | 行高 |
|---|---|---|---|---|
| H1 主标题 | `"Noto Serif SC", "Songti SC", "SimSun", serif` | `clamp(44px, 8vw, 96px)` | 700 | 1.1 |
| H2 区块标题 | 同上 | `clamp(28px, 4vw, 52px)` | 700 | 1.2 |
| 卡片标题 | 同上 | 24px | 600 | 1.3 |
| 正文 | `"Noto Sans SC", "Microsoft YaHei", system-ui, sans-serif` | 17px | 400 | 1.8 |
| 辅助文字 | 同上 | 14px | 400 | 1.6 |
| 栏目标签 | 同上 | 12px | 500 | 字距 0.12em、大写 |

### 2.6 动效参数

| 动效 | 参数 |
|---|---|
| ① 卡片悬停 | `transform: translateY(-8px)`；图片 `scale(1.06)`；阴影换"悬停值"；过渡 `280ms cubic-bezier(0.22, 1, 0.36, 1)` |
| ② 滚动淡入 | 初始 `opacity:0; translateY(24px)` → 归位；时长 `500ms ease-out`；触发阈值视口 15%；同组错开 `80ms` |
| ⑤ 按钮光扫 | `::after` 一条 `linear-gradient(105deg, transparent 30%, rgba(255,255,255,0.55) 50%, transparent 70%)` 从左到右扫过，`700ms ease-in-out`，hover 触发 |
| 全局约束 | 自动播的要含蓄（②），用户触发的可明显（①⑤）；`prefers-reduced-motion: reduce` 时全部降级为只淡入 |

### 2.7 响应式断点

| 断点 | 布局 |
|---|---|
| < 640px（手机） | 单列；标题用 clamp 最小值；按钮全宽；卡片纵向 |
| 640–1023px（平板） | 卡片 2 列 |
| ≥ 1024px（桌面） | 卡片 3 列（第 4、5 张跨列形成杂志错落感）；内容最大宽 1200px |

## 4. 分阶段计划（10 个阶段）

### 阶段 0 · React 速成 + 环境准备
- **做什么**：安装/检查 Node.js、Git；学习 8 个 React 核心概念（JSX、组件、props、useState、useEffect、列表渲染、事件、CSS 组织方式）
- **产出**：能跑通 `npm create vite@latest` 的环境 + 心智模型
- **验收**：`node -v`、`npm -v`、`git -v` 有版本号；能说出"组件就是返回 JSX 的函数"

### 阶段 1 · 项目初始化 + 设计令牌
- **做什么**：在当前目录脚手架 Vite+React；建 `tokens.css`（全部变量按 §2 写死）+ `global.css`
- **产出**：可运行的空项目 + 令牌文件
- **验收**：`npm run dev` 打开页面不报错；在 DevTools 里能看到 CSS 变量

### 阶段 2 · 组件拆分 + 静态内容
- **做什么**：写 `data/cities.js`（五城文案）；建 Hero / Highlights / About / Footer 四个组件并组装进 App
- **产出**：只有结构和文字、还没样式（或极简样式）的完整页面
- **验收**：页面从上到下能读通：标题 → 5 卡片 → 介绍 → 页脚

### 阶段 3 · 视觉样式（A+B+E+d 落地）
- **做什么**：按 §1/§2 给四个组件上样式；渐变彩色背景色块；玻璃卡；新拟态按钮；细线分隔与栏目标签
- **产出**：静态但已经好看的完整视觉稿
- **验收**：颜色/间距/圆角/阴影/字体全部与 §2 数值一致

### 阶段 4 · 三个动效
- **做什么**：① 卡片悬停抬升+发光+图片放大 ② 滚动淡入（IntersectionObserver 封装成 `Reveal`）⑤ 按钮光扫；全部纯 CSS + 原生 JS，无动画库；加 `prefers-reduced-motion`
- **产出**：动效完整的页面
- **验收**：三个动效逐个手动测试通过；关掉动画偏好后不突兀

### 阶段 5 · 响应式适配
- **做什么**：按 §2.7 调整三个断点布局；用浏览器设备模拟逐个尺寸检查
- **产出**：手机/平板/桌面都正常的页面
- **验收**：375px、768px、1280px 三档无横向滚动、无文字溢出

### 阶段 6 · 图片素材机制（先 a 后 c）
- **做什么**：默认用 CSS 渐变 + SVG 自绘图案表现五城；把"换图"做成改一行代码的事（`src` 优先用照片，没有就回退渐变）
- **产出**：不依赖任何外链图片的页面 + 你以后能自己换照片的机制
- **验收**：断网打开页面依然完整好看

### 阶段 7 · 文档撰写（DESIGN_SYSTEM.md + README.md）
- **做什么**：DESIGN_SYSTEM.md 把 §2 五项数值原样写进去；README 写项目简介、运行方式、技术栈、截图、Gitee 链接
- **产出**：两份文档
- **验收**：DESIGN_SYSTEM 五项（颜色/间距/圆角/阴影/字体）都有**具体数值**，无"约等于""较柔和"这类模糊词

### 阶段 8 · 自测 + 截图（你自己动手）
- **做什么**：按自测清单过一遍；用浏览器截 4-5 张图存 `screenshots/`
- **建议截图清单**：
  1. 桌面端 Hero 全屏（1280×800）
  2. 卡片悬停状态（抬升+发光那一刻）
  3. 手机端 375px 整页
  4. 介绍段落 + 页脚
- **截图方法**：F12 → 设备模拟 → 选尺寸 → `Ctrl+Shift+P` 输入 "screenshot" 可截整页；或直接用系统截图工具
- **验收**：截图 ≥2 张、清晰、能体现设计与动效

### 阶段 9 · Git 提交 + Gitee 推送
- **做什么**：`git init` → `.gitignore`（排除 `node_modules/`、`dist/`）→ 分阶段 commit → Gitee 建新仓库 `travel-gallery` → 推送
- **产出**：Gitee 项目链接（写回 README）
- **验收**：Gitee 网页能打开仓库、能看到源码与截图
- **常用命令**：

```bash
git init
git add .
git commit -m "feat: 旅游画廊首页（React + Vite）"
git remote add origin https://gitee.com/<你的用户名>/travel-gallery.git
git push -u origin master
```

## 5. 阶段依赖与顺序

```
阶段0（环境+React速成）
   └─> 阶段1（脚手架+令牌）
          └─> 阶段2（结构+文案）
                 └─> 阶段3（样式）
                        └─> 阶段4（动效）──> 阶段5（响应式）
                                                └─> 阶段6（图片机制）
                                                       └─> 阶段7（文档）
                                                              └─> 阶段8（截图）→ 阶段9（推送）
```

- 阶段 4 和 5 可以微调顺序，但**先动效后响应式**更容易发现问题
- 阶段 7 的文档数值必须等阶段 3 定稿后再写，避免数字对不上

## 6. 给 Agent 提示词的使用方法

1. 打开 `docs/STAGE_PROMPTS.md`，**按阶段顺序**复制提示词
2. 每个阶段开一个新对话粘贴（或同一对话连续发也行），做完一个阶段、验收通过再发下一个
3. 每条提示词都要求 Agent **边做边讲解 React 知识**——你是在学 React，不是只拿结果
4. 卡住时把报错原文发给 Agent，不要自己猜
